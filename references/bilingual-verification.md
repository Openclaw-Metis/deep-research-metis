# 雙語驗證模型

英文中心的驗證器在繁體中文報告上會系統性誤判：句子切分只認 ASCII 句號、長度以空白斷詞、主張支撐度以英文詞彙重疊計分，於是整節中文被視為單一句子、字數被低估、幾乎每個主張都落入 `unsupported`。本 skill 的三個檢查改以下列規則運作。

## 句子切分

`claim-ledger.extract_claims` 以 `。！？` 為斷點；`.?!` 只在後面接空白、行尾或引用標記時才算斷點，因此 `3.5 TWh`、`12.4%` 與 `arxiv.org` 不會斷句，`U.S.`、`e.g.`、`et al.` 這類縮寫也不會。分號不斷句，子句共用句尾引用。斷點後緊接的引用標記留在同一句，所以「……成長 [1]。」與「……成長。[1]」都是一個帶引用的主張。

硬換行的相鄰行合併為同一段再切句。表格資料列以 `origin=table` 進入抽取，表頭與分隔列不算主張。程式碼區塊、引言列與書目章節不進入主張抽取。

## 引用標記

`[1]`、`[1, 2]`、`[1-3]`、`[1][2]`、全形 `［1］` 與 `【1】` 都是有效引用，範圍展開為個別編號。書目條目可寫成 `[1] 標題 網址` 或 `1. 標題 網址`。

## 長度量測

`bilingual_length` 把 CJK 字元逐字計數、拉丁字串以詞計數，兩者相加。這讓 `check_structure` 的 `min_length` 對中英文都有一致意義，不會因為中文沒有空白而低估篇幅。

## 章節比對

章節標題以中英文別名表比對，因此 `## Executive Summary 執行摘要`、`## 執行摘要` 與 `## Executive Summary` 都算通過。別名表是隨 Skill 交付的資料資產，新增別名不需要改程式。

書目章節多一道內容判定：標題含別名，且章節內至少一半的行看起來像書目條目才算。`## 資料來源比較` 與 `## Sources of Uncertainty` 是正文，其中的主張照常受檢；`## 參考來源與延伸閱讀` 下列著條目時仍是書目。

## 主張分類

含引用的句子是 `cited`。其餘句子含數量時是 `quantitative-uncited`，在支撐度檢查判為 error。年份、第 N 節、表 N、Figure N 不算數量，因此「詳見第 3 節」不會被要求引用；`2000 MW` 這類帶單位的數字仍算。標題含 `Methodology`、`研究方法` 或 `檢索紀錄` 的章節裡，未引用的句子歸類為 `process`，因為檢索次數是本研究的流程紀錄，不是外部事實主張。

## 主張支撐度計分

`report-verify.check_claim_support` 先判斷主張與引文的主要書寫系統：

- **同語系（same-script-lexical）**：中文對中文以字元 bigram 覆蓋率計分，英文對英文以詞彙覆蓋率計分。`supported` 門檻 0.45，`partial` 門檻 0.22。
- **跨語系（cross-script-anchor）**：中文主張引用英文原文時，逐字重疊必然為零，因此改以翻譯後仍會保留的錨點計分：數字、單位、百分比、縮寫與專有名詞。門檻較嚴，`supported` 0.60、`partial` 0.34。
- **無錨點（insufficient-signal）**：跨語系但主張沒有任何數字或專有名詞可對照時，判為 `unverifiable` 並回傳 warning，建議補上可對照的錨點或同語言引文。只有在呼叫端明示 `require_cross_language_anchor` 時才升級為 error。

一個主張引用多則引文時，逐則判定後取最強結果，順序為 `supported`、`partial`、`unsupported`、`unverifiable`，判定與引文寫入順序無關。`unsupported` 排在 `unverifiable` 之前，因為比對過但不符是真實訊號，無法比對則沒有訊號。

行內引用標記在計分前一律移除，否則 `[2]` 會被當成主張中的數字「2」而扭曲錨點比對。

## 數字比對

字詞覆蓋率看不到被改動的數字：「成長 81%」與「成長 18%」對同一則引文的分數完全相同。因此帶引用主張的每個數字都必須出現在所引來源的引文內，比對以數值為準，`1,280` 與 `1280` 相同。主張含「約」「近」「about」「roughly」等概數詞時容許 5% 差距，所以 `約 12%` 對 `12.4%` 通過，`about 30%` 對 `18%` 不通過。

不符時回報 `claim_number_unmatched` 並列出 `unmatched_numbers`，`supported` 降為 `partial`；`strict` 下是 error。這項比對只看數值，不比單位，也不換算：`40 億美元` 對 `4 billion` 會不符，補一則保留原始數字的引文即可。

表格列是片段而不是句子，字詞覆蓋率沒有意義，因此有數字的列以數字是否相符判定，沒有數字的列門檻採 `partial`。

## 判定語彙

`supported` 表示字詞與數字都對得上；`partial` 表示部分重疊，建議補強；`unsupported` 表示重疊過低，預設在 `strict` 模式下判為 error；`unverifiable` 表示跨語言且無錨點，需要人工補證而非自動放行。四種判定都寫入 `claim_support.json`，並附上 `method` 欄位說明分數的來源方法。

## 機械檢查的邊界

這些檢查比對字詞與數字，不理解語意。主張把「不會成長」寫成「會成長」、把相關寫成因果、把區域數據寫成全球，分數都可能很高；正確但用詞完全不同的改寫則可能被判為 `unsupported`。因此 `supported` 的意思是「用語與數字對得上」，不是「語意已查證」，PASS 後仍要由 agent 閱讀關鍵主張與其引文。

報告自己的判讀與推論不掛引用。「兩者的因果方向仍需更多資料 [1, 3]」這類句子來源並沒有說過，會被判為 `unsupported`，這個判定是對的：引用只標在來源確實說過的事實上。
